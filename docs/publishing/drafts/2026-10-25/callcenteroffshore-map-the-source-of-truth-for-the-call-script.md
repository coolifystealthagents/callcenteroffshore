# Map the source of truth for the call script

## Why the call script needs its own control

A team working in offshore call center operations can complete a task and still leave the next person unable to verify it. The control for the call script exists to make the work reconstructable from a source, a decision, and a close.

The cost is not only rework. When the call script record is thin, managers spend time asking what changed, customers hear a different version, and the next reviewer has to rebuild the story from memory.

Treat the control as a queue item with an owner, a due time, and a close condition. A task that has no close condition becomes an open loop that survives the week.

Do not copy a value from a prior record for the call script because it looks familiar. Reopen the source, confirm the version, and record what changed.

## Start with the source record

Begin with the record that governs the call script. Record who created it, the version or date observed, the field it supports, and the person who can confirm it.

Keep the source and the interpretation in separate fields. A forwarded message or a verbal confirmation can be a lead, but it is not proof that the record changed.

When two sources disagree, preserve both values and label the discrepancy. Do not overwrite the earlier value to make the report look clean.

Close the loop with the person who raised the call script issue. A record that is internally complete but never confirmed by the requester is only half closed.

## Separate preparation from approval

Name the owner before the VA prepares any action. The VA may collect, compare, label, calculate, and route; the call center manager decides whether the evidence is enough.

Write the boundary into the task brief. Name the systems the VA may use, the fields they may change, and the questions they must route.

A complete packet is not an approval. A drafted message, a proposed schedule, or a reconciled total still needs the named owner decision when policy or risk is involved.

## Build the daily routine

Build a short daily routine for the call script: open the queue, check the source, record the exception, and leave a next action with a time.

Use the same fields every day. Consistency makes the work comparable and lets a reviewer spot a missing source without reading the whole thread.

Keep the queue small enough to finish. A long queue hides the oldest exception and makes the monthly report look better than the operation.

Keep the call script queue separate from the general inbox. A shared queue without a named owner hides the oldest item and makes the weekly report look cleaner than the work.

## Handle exceptions before they age

Define reason codes for the call script: missing evidence, identity mismatch, conflicting record, stale version, unavailable owner, access failure, and scope change.

Preserve the original request and the correction. A later reviewer should see what was known when the first action was taken.

If the exception affects pay, safety, access, legal, or a customer commitment, stop the dependent action and route it. Urgency is not permission to work around the control.

When a source is unavailable, record that fact instead of leaving the field blank. Missing, unavailable, and confirmed negative are three different states and should not be collapsed.

## Verify, close, and review

Close the call script only when the destination record shows the approved change. A sent message or a closed ticket is not proof that the schedule, ledger, access, or assignment changed.

Reconcile open cases at the end of the day and explain the carryover. A case that is silently carried forward becomes an aging exception.

Review a sample each month. Check the source, the approval, the execution, and the confirmation. A repeated gap should change the procedure, not only the coaching.

Use a short reason code for every exception on the call script. The code should describe the evidence problem, not the person who found it.

## What the VA may prepare and what the call center manager decides

For call center and support managers, the useful split is preparation versus authority. The VA can assemble the call script packet, check the fields, and write a precise question; the call center manager owns the decision that changes money, policy, access, or a customer promise.

Write the split in plain language and keep it next to the queue. A boundary that exists only in a training call disappears when volume rises or a new person joins.

The VA should stop when the source is missing, the records conflict, the request exceeds the written scope, or the rule has not been approved. A stop is cheaper than a correction after release.

Review one case involving the call script end to end in the weekly meeting. Check the source, the decision, the destination record, and the confirmation rather than only the completion count.

## A weekly evidence review for the call script

Set one recurring point each week to review the call script queue: the oldest items, the blocked items, and one item that was corrected. Keep the meeting short and decision-focused.

Use the same sample rule every week. A consistent sample shows whether a change helped. A different sample each week shows only that someone looked.

End the review with one process change, one owner, and one check date. If nothing changes, the review becomes another status meeting.

If the call script rule changes, keep the earlier classification and apply the new rule to later cases. A definition that changes quietly makes the trend unreadable.

## What to fix first

Fix the source before you fix the report. If the call script record cannot show the version, the owner, and the close condition, a new dashboard will only make the gap easier to see.

Fix the stop rule before you add training. People need to know which cases must not move without a decision, not only which fields to complete.

Fix the template before you ask for more volume. A short form that is used under pressure beats a long form that is skipped when the queue is full.

Keep a named backup for the call script owner. Coverage during leave or a time-zone gap should be written into the routine, not improvised when the owner is unavailable.
